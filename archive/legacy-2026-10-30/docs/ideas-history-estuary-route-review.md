# Estuary whole-route review: causal and operand audit

27 October 2026. Independent source-exposed review of `ideas-history-estuary-named-candidate.md` and `ideas-history-estuary-whole-routes.md`. Paper review only: no implementation, player, enjoyment or length finding. The earlier independent challenge remains unchanged.

## Verdict

The candidate now has a useful non-Boolean core: a function can operate on different continuous trajectories; replay and live following can visibly diverge; translation has a genuine information-loss boundary. The whole-route claim is nevertheless **not yet causally complete**. In particular, N21 imports its essential score, N26–28 do not establish a new capability for the former teacher, and the delivery chronology lacks a consistent activity rule.

These are repairable specification holes, not reasons to reject easy progress or the universal adapter. Repair them before describing either route as reaching all six projects. Keep the thirty rows explicitly prospective; the repairs need not increase the eventual action count if an honest whole method constructs the needed object.

## 1. Type the interfaces before tracing learning

The candidate does not specify enough to check N7, N12–13, N18–20, N23 or N29 end to end.

- Long Tide has no exact knots, amplitude range or units, but N7 applies an angle/pressure map. State a tide signal domain and its conversion. For example a declared dimensionless height trajectory can use its own height-to-pressure correspondence. Do not silently call tide height an angle.
- `90-90p` is an angular command on the stated reversed actuator, not a normalized command. The formula is correct given degrees; the adjective is not.
- Pressure Guide is described alternately as an interface, an inverse-map controller and an activity. State its input and output: e.g. pressure sensor `p=a/90`, identity angular actuator `a=u`, controller `u=90p`.
- Ilen's initial pressure-output interface does not automatically permit angular actuator commands. N20 needs an explicit binding: Ilen produces pressure, and a declared actuator maps that pressure to instrument angle; or Ilen has a separately disclosed angular-control interface. Either is fine, but the actor cannot silently gain hardware from learning a function.
- N18 must select the canonical angle trajectory of Journey B, not apply angle-to-pressure again to an already pressure-valued viewpoint trace. The episode can retain both canonical process and observed channel, with the chosen source visible.
- N29 needs the distant interface stated at setup. “Compatible” cannot hide construction of whatever makes the goal true.

**Minimal fix:** a compact interface table giving process domain, sensor function, actor output channel, actuator function and record channels for each location. Bind N10/N12/N19/N23 to those named ports. This is specification, not an extra installation ceremony.

## 2. Separate using a tool from acquiring its practice

N2 globally constructs Following Practice; N10 and N12 construct adapted controllers before either relative experiences their activity. N11/N13 then say their repertoires differ, but no rule yet distinguishes:

1. an external controller serving an actor;
2. an actor executing a supplied program for this run;
3. that actor retaining the program as a reusable capability.

The route can use an entirely reasonable **perform-and-retain** rule: combining a willing actor with a compatible practice both teaches it and enacts the bound activity. State that rule once, including Ilen at N8 and the host at N23. It makes N11/N13 and reunion's later repertoire difference coherent without new paperwork.

Do not claim that the physical experience itself discovered the inverse function: the function was already supplied. The relatives learn/use different publicly authored practices during different actual encounters and subsequently teach them. That narrower relation still meets the proposed life. Direct instruction remains equally valid where travel is not the goal.

N14 also needs selected accounts to contain **the actual practiced executable methods**, not just output traces. A single demonstration trace does not uniquely determine a general controller. Retaining the controller used in the episode avoids an unspecified inference engine.

N14 currently says transfer occurs immediately, while N15 says it occurs there. Choose one: N14 constructs a callable reciprocal lesson from two records; N15 enacts it. Alternatively combine them in one legal named result. The same transfer must not be credited twice.

## 3. N21 imports the central performance rather than constructing it

No earlier row constructs `Linked visual/tactile score`. There is a tactile tide score and an expedition replay, but no declared composition joining **actual sweep and tide**, the requirement of project3. N18 is derived from Journey B, not Beacon A. “Existing scores remain available” does not supply the missing relation.

**Fix:** explicitly construct a named composition from the actual A-derived visual score and Tidal Touch, with a declared phase alignment. For example, both become four-unit scores starting together; list which channel each role produces and exactly which order/simultaneity predicates are preserved. A meaningful result such as **Tide-and-Light Canon** can be one binary combination. Enact it with a previously defined compatible pair. Do not call an arbitrary list of actors “willing performers” unless it is a typed role assignment with visible members and interfaces.

The same score must then be the object sent at N22 and performed at N30. This repair gives project3 a causal witness; it is not an anti-shortcut prerequisite.

## 4. The reciprocal-school branch currently teaches a repeat, not new capability

Later C is public from setup and already enacted by Ilen at N20. N26 creates a later occurrence with **identical trajectory**. The host has a universal following relation and records C; the former teacher may already have access to C's exact literal schedule. N28 enacts C again. This shows a new receiving episode and possibly learning a stored replay, but does not by itself establish the stronger promise of a “corresponding new usable practice.” New occurrence identity is insufficient.

This is not fixed by hiding C's values or forbidding literal authoring.

**Minimal honest repair:** identify the former teacher and its before-repertoire, then have the successor construct and teach a specific new callable result from its occurrence—for example an explicitly transformed C replay whose function/score is absent from that teacher's repertoire. Show the teacher using it in a later context. The player could directly author the same result; choosing the successor's lesson establishes the reciprocal relationship without making it the only route. No intellectual invention needs to be claimed.

Alternatively weaken the project to **the former teacher receives a successor's fresh account**. Then a repeated C run can qualify as a later reported occurrence, but stop advertising this as changed capability. The stronger current project4 remains unproven until one of these choices is made.

N23–25 must also name the original teacher/officeholder and a demonstration they actually performed. “Demonstrated tracking practice” otherwise imports both a demonstration and the teacher's institutional history.

## 5. Delivery and succession need one clock, not convenient rows

The declared rule says a sent message arrives after the **next whole local activity**. N22 sends the score. N24 then says both schools receive invitations, while N26 says earlier messages now arrive. Are teaching, agreeing, succession and score construction activities? If N23 is a whole local activity, delivery has already occurred. If not, that boundary must be explicit. A known agreed future event is also not constructed solely by announcing that both schools are willing.

**Minimal fix:** identify clock-advancing actions precisely. A simple rule is “enacting a process or performance advances one epoch; pure constructions, teaching and role changes do not.” N24 queues invitations rather than receiving them. N25 changes the local role holder. N26 enacts a run, advancing delivery to that holder and the remote group. A disclosed standing voluntary participation policy may accept the invitation on receipt; no unnecessary negotiation clicks are needed. State the event epoch and how it follows N29 if N29 itself advances time.

Name the former holder's personal project and actually enact its continuation, possibly concurrently with a whole festival activity. Keeping a field called `personal activity` is not the stated continuing life. Project6 needs actual role-addressed delivery after succession, not merely a successor coincidentally attending the festival.

## Flags, bags and legitimate compression

- **Continuing School** currently wraps request routing. That is honestly a routing change; it earns a larger consequence only when the later request is delivered and performed. No extra Living Alumni construction is needed.
- **Reunion Practice** and **Returning Family** risk wrapping one repertoire transfer twice. Define method versus enactment or merge them.
- **Rendezvous Practice** risks being an agreed-event flag until receipt/adoption/time are explicit.
- **Selected family accounts**, **willing performers**, **shared future event**, and **demonstrated practice** are not yet concrete operands. Name their typed contents or provide their producing action. A two-account lesson or two-role ensemble is legitimate; an unrestricted context bag is not.
- **Borrowed Horizon → live practice** is sound if the transformed score retains its explicit map as metadata and the live practice uses that map, not an illicit inferred inverse of arbitrary samples. The document already points this way; preserve it.

The complete route inherits the same gaps; compression does not repair them. Its universal adapter correctly supplies `g⁻¹(f⁻¹(input))` for declared invertible maps. It legitimately collapses much instrumental learning. With direct authoring and a universal repertoire, the player may deliberately choose a reciprocal lesson rather than need it; distinguish that chosen relationship from a capability shortage. This is not evidence against ordinary discovery pleasure.

**Recommended next paper edit:** fix types, produce the actual shared score, identify teacher/repertoire change, and publish a four-column chronology of queued messages, advancing activity, current holder and actual recipient. Then recheck both whole routes without adding mandatory adversity or claiming thirty measured actions.

## Addendum — executable specification v1 check

27 October 2026, after publication of `ideas-history-estuary-executable-spec.md`. This checks that new contract, not an implementation. The earlier review above remains the accurate criticism of the earlier routes.

### Repairs accepted

- Reunion now transfers on family+teaching enactment; the duplicate family-bound install step is removed.
- The shared score is explicitly constructed and its two channels decode to the same actual sweep. Removing the unconstructed tide component is an honest endpoint revision, not a false claim to have built it.
- Exact tide knots, score presentation, retained latent trajectory and perform-and-retain semantics substantially settle the earlier type/learning holes.
- Mara is explicitly the original school holder. Later D differs from C; teaching its specific stored replay can add a real episode-specific capability to Mara, demonstrated without live input. This is reciprocal learning of a new replay, not inferred general intelligence. The public availability of D does not invalidate that chosen lesson: direct authorship remains a valid alternative route to the output.
- Queueing, role transfer, receipt and adoption now have a deterministic order. Delivery occurs at the start of the next activity epoch, before its performance. A festival that delivers its own invitation is legitimate under this stated law; it must not be rejected merely because no separate receiving click occurred.

No remaining **paper-level blocker** requires replacing the six-project collection. Four details should be made explicit in code/tests rather than resolved by convenient inference:

1. **Actor output versus instrument command.** The spec's pressure interface senses pressure but actuates angle; Ilen emits pressure. Keep separate typed ports for performance output and controller command. A pressure-output actor cannot silently supply an angular command because a score has a latent angle trajectory. Either a declared transducer converts the pressure or the actor is operating a controller with that command port. The direct signal-output goals do not require adding instrument hardware.
2. **Activity ordering.** At an activity, advance epoch, deliver/adopt, then resolve the performer from the current role and perform. Validation must allow a festival's same-activity delivery/adoption shortcut. Failed-activity clock behavior also needs a consistent declared rule; do not let an invalid request secretly become a free wait.
3. **Replay novelty.** Define an equivalent retained replay by decoded trajectory and relevant timing, not score name/source ID alone. Distinct D source identity is not itself novelty. The before-repertoire check should be at the receipt/lesson boundary, with succession and D encounter genuinely preceding the lesson. Universal live following is not a stored D replay, whereas an already retained literal D replay is.
4. **Actual local lives.** Endpoint5 currently requires that prior lives remain, not that the distant school's own baseline activity actually continues after participation. This is weaker than the earlier project wording. If continued local activity is still desired, enact and check its baseline practice after or alongside the shared event; otherwise report the endpoint narrowly as non-erasure, not demonstrated ongoing local life.

### One substantive scope narrowing to preserve in reporting

Endpoint2 now accepts each relative **reproducing the other's episode**, rather than necessarily using the other's general controller in a new situation. That is a coherent transferable replay capability, and cannot be dismissed as a flag when actual outputs are checked. But it is weaker than the earlier claim that the local learned pressure-guided operation and the traveller learned reversed tracking. A score-only exchange does not establish those general practices.

For the strongest normal witness, retain both: execute the exchanged bound controller on a later input and replay the other relative's episode where requested. Alternatively explicitly describe the endpoint as exchange of episode-specific performances. Do not claim general interface-learning evidence from a replay-only witness. This need not become mandatory extra steps in the complete/control routes if one lawful enactment demonstrates the actual relevant behavior.

### Six endpoints after repair

All six now have plausible finite witnesses: transformed tide; genuinely forked and diverged lives with reciprocal replay; dual-channel sweep; successor D lesson; delivered distant performance; and role-addressed cooperation after handover plus a former holder's later personal act. The D replay can itself be that personal act if it is genuinely performed independently of school routing—no artificial second activity is needed.

The remaining implementation challenge is ensuring those predicates inspect real output, event order and retained methods rather than trusting names. Universal adapters, direct instruction, exact literal schedules and convenient festival delivery remain legal. This review establishes specification coherence with the qualifications above, not executable correctness, enjoyment, duration or a200-decision result.
