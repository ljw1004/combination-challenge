## Counterexamples found and repaired by implementer

1. **Remote retained controller incorrectly rejected.** A Distant identity/B run generated a new score and then treated its own local output as undelivered instruction. The remote actor now executes an already-retained controller without that false rejection.
2. **Generated IDs overwrote legitimate authored scores.** Authoring and retaining `run-score-2` as D, followed by Sori's A run, changed Mara's retained replay to A. Collision-safe generated IDs now preserve the earlier score and episodes.
3. **Remote direct score application rejected rather than transmitted.** Fresh remote `perform` now queues personal instruction without adoption, output or epoch advancement; a later activity delivers it.
4. **Unrelated solo transmission credited as shared-score transmission.** Replacing both route invitations with the solo Tide score previously left all six endpoints true. Project5 now requires actual earlier local shared performance of the transmitted score.
5. **Valid personal transmission excluded by role-name password.** Personally sending the actual shared score to Distant, enacting it, then continuing local life now qualifies without requiring the `Far` role-addressed path.
6. **Continuing local life required exact `baseline` score ID.** Distant's retained identity controller actually reproducing B now qualifies as continued baseline behavior; the named baseline replay is not compulsory.

The implementer preserved earlier failures under `results/ideas-history-estuary-development/prefreeze-failures.txt`. The independent test file preserves the counterexamples as expected-correct regressions.
