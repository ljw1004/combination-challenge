# Before implementation: the continuous kitchen collection

New candidate identity; archived four-scene starter and saucepan pilot are immutable. Target roughly 180–220 goal-route combinations, not a tiny route hidden behind an optional catalogue. One continuous narrative: cooks in a working food-history collection prepare meals for visitors and borrow one another's actual preparations. The collection permits time compression, but never asserts a single universal chronology or that industrial food supersedes earlier food. No parallel non-food narrative: alternating kitchen and abstract historical research would interrupt the strongest physical through-line and invite paper-token padding.

Each stage's imports will be derived from the recipes actually playable there, not from all future needs. Required exports are earned at their source; missing creations cannot be conjured by a material cache. New caches name the local worker and concrete stocks/tools they supply. Goals will be real dishes and useful preparations, with intermediate flags and reveal dependencies where a listed preparation feeds another goal. No carryover paragraphs in scene prose.

Every input has an authored lifecycle: reusable tools retain; shareable ingredient stocks/preparations retain for named branches; a single dish under preparation transforms at its own position; additions incorporate. All removal remains an explicit recipe declaration. No runtime changes planned.

Verification will report route/corpus counts separately, chapter import witnesses, finite directed graph, recipe coverage, width replays, checkpoints, exact replacement positions, retain/integration behavior, undo/restore, and source runtime hashes. This is source-aware logical evidence only, not fresh-player fun, visual touch QA, or food safety validation.
