# Creation icon recovery

This active study recovers the selected painted subjects from the completed [Creation production sources](../../../archive/2026.11.05%20creation%20study/production/README.md). The archived masters and records remain unchanged. The [icon guide](../../../docs/icon-guide.md) owns the artwork workflow; this directory owns the selected geometry and mechanical export for this revision.

The initial plan contains all 206 earlier identities. It exports an ordinary 256×256 image for each and a `large-<slug>.webp` 384×384 presentation for the 11 formerly fixed identities other than Sea cave. These filenames describe image size, not game behavior. Sea cave has only its ordinary icon here; its landscape receiver is separate work. The revised manuscript may retire identities by removing their entries from the plan and their unused files from the study. The exporter reports unselected WebPs and never deletes them automatically.

## Accepted recovery and preservation limits

The previous extraction sometimes clipped a painted disk at a nominal atlas-cell edge while admitting a neighboring rim. Multiplying the source alpha by a circle also retained slightly translucent interiors. This recovery uses explicit reviewed source geometry, opaque painted RGB and a separate exact frame.

`icon-plan.json` binds each selected master to a repository-relative path and SHA-256, and each identity to its selected ellipse. Its geometry was derived from source alpha boundaries during the perimeter audit and accepted after inspection of before/after and frame-cover proofs. The production exporter does not run that detector. No audit measurements, temporary comparisons or proof bundles are retained here, and the source paintings are not duplicated.

The accepted recovery maps the source ellipse to a circle. This corrects the source aspect ratio by up to about 3.7% and replaces the outer 3.673% of its radius with a narrow deterministic rim. Those small aspect and edge-cover changes were explicitly accepted; this is not uniform scaling or a claim that every source-edge pixel survives. The selected subjects remain the original paintings. No new subject content is generated by this process.

The frame is centered in both output sizes: outer radius `0.490 × size`, outer ochre beginning at `0.486 × size`, and ivory beginning at `0.472 × size`. Inside the rim, the exporter samples the source RGB with LANCZOS. It ignores accidental near-opaque source alpha for recovered paintings. A separate four-times supersampled circle mask uses area averaging, giving an exactly opaque interior, a transparent exterior and antialiasing only at the perimeter. Output WebPs use lossless encoding; source resampling and the accepted framing operation still change pixels.

The authoring agent inspected all 206 provisional recoveries at 64px and representative large versions at 96px. These are informed mechanical/artwork checks. An independent informed review subsequently inspected all 206 ordinary icons at 64px, all eleven large exports at 96px and eight edge-sensitive source/export pairs at 256px, accepting the recovery without significant subject loss, neighboring fragments or visible seams, and no human recognition, preference or enjoyment claim follows from these checks.

The initial 217 production exports match the accepted provisional image bytes exactly, with the 11 larger files renamed from `fixed-` to `large-` and the larger Sea cave omitted. All passed exact interior-opacity, transparent-exterior and centered-boundary checks. Disposable full-bleed fixtures checked opaque RGB preservation, both sizes, invocation from another working directory, read-only verification, and rejection of changed source hashes, nonsquare crops and nonopaque square sources without changing existing outputs.

## Reproduce and verify

Run from the repository root; `uv` reads the script's pinned Pillow and NumPy dependencies. Repository discovery also permits invoking the script by its full path from another working directory.

```sh
uv run projects/creation-study/production/export-icons.py
uv run projects/creation-study/production/export-icons.py --dry-run
uv run projects/creation-study/production/export-icons.py --verify
```

The default export writes only selected icons under `projects/creation-study/assets/icons/` and `selected-exports.json` beside this README. The record binds source hashes, geometry, plan, renderer, encoding-library versions, dimensions and every selected output's SHA-256. Source hash or geometry failures stop before output writing. Matching files are left in place. All inputs and renders are validated before the output family is updated.

`--dry-run` checks inputs, selected geometry, the record and output hashes without writing. `--verify` additionally re-renders every selected image in memory and requires identical encoded bytes. An environment/encoder mismatch is reported rather than silently treated as reproducible. Both commands return a nonzero status on failure and report unselected WebPs separately.

For a disposable alternative export, supply an explicit destination:

```sh
uv run projects/creation-study/production/export-icons.py --output runs/creation-export-check
uv run projects/creation-study/production/export-icons.py --output runs/creation-export-check --verify
```

A custom output receives its own `selected-exports.json`; it does not replace the production record. `--plan` selects another authored plan, and `--record` explicitly selects a record path. These options never change the source files. The standard exporter does not write into `stories/creation` or modify application behavior.

## Add a full-bleed painting

New paintings should be opaque and fill their square, with no generated rim or transparency. Keep the identifying subject inside the intended circle with breathing room; the final visible picture radius is `0.472 × crop width`. The corner content is deliberately outside the circular window. Artwork may extend beyond it when that is intentional, such as a landscape continuing out of view.

Retain a selected new master and its exact request here under `masters/` and `requests/`. Add a source entry with its repository-relative path and SHA-256, then select it with explicit square geometry:

```json
{
  "name": "Example identity",
  "slug": "example-identity",
  "source": "example-master",
  "geometry": {
    "kind": "square",
    "bounds": [0, 0, 1024, 1024]
  },
  "large": false
}
```

Bounds use source-pixel edge coordinates, with right and bottom exclusive. They must describe a positive square contained in the source. Every pixel in that selected square must be fully opaque; translucent sources are rejected. A square can also select an explicitly authored cell in a larger opaque atlas. The exporter uniformly maps that square to the output and applies the same centered frame and alpha mask, without detecting a painted border or using generated alpha to infer geometry.

For recovered atlas art, `kind: "ellipse"` instead requires an explicit `center: [x, y]` and `radii: [rx, ry]`. Edit these only after inspecting the source and the resulting edge coverage; do not copy bounds from the earlier cropped runtime image. Changing a selected source requires deliberately updating its hash and re-exporting before verification can pass.
