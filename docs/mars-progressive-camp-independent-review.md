**The previous world is actually retained.** Every checked wrapper transition equals the frozen engine transition on the existing camp; reaching a milestone creates no new world, installations, knowledge reset or scenario switch. The original shell survives the incremental path unchanged and still encloses the tray. A new installed lead has its own identity and receives its actual lamp.

**Current and historical claims are separate.** The public status uses current enclosure and illumination conjoined with earned observer location. A remembered garden milestone cannot complete a dark garden. Conversely, the observer need not keep receiving after locating the camp. Both milestones may first occur on the same action. Underlying garden `won` does not leak into public project completion.

**Blueprints are not earlier physical objects.** Reusing a known composite creates independent installation identities. Modifying a lead, shell or panel changes the targeted existing assembly. No automatic construction, reset command, resource limit, compulsory detour or prohibition after success was added. All base legal actions and exact results remain public.

## Capture and disclosure review

The CLI records initialization, views, explicit previews, actions, checkpoint/report objects and finish events with exact outputs, physical state and a replay/hash chain. Tests establish input purity, deterministic replay, rejection behavior, refusal to overwrite sessions, rejection of resealed false outputs and source drift, and the distinction between session finish and physical legality. All automatically exposed previews are present in the associated observation; explicit preview requests have separate events.

An initial disclosure concern was fixed before freeze: the guide is now explicitly **operator-only**, because it identifies a known solution and links analyst witnesses. It must not be the fresh player's reading assignment. Give that player neutral commands and actual public observations/laws, not source, this review, the proposal, witnesses or earlier player reports. Do not remove lawful winning previews to compensate.

Initialization now requires the exact public assignment and an actual participant identifier. Record model metadata only if available. The coordinator must additionally retain any separately delivered checkpoint/final questions with verbatim answers; a capture cannot infer prose delivered outside the CLI. The checkpoint should describe the player's own immediate intention rather than suggest a route or a particular installation to preserve.

## Interpretation boundary

The implementation supports the narrow experimental question. It does not establish that progression feels valuable, that the opening needs improvement, that difficult choices are missing, or that this is a sustained game. If both goals complete together, preserve that valid ending and say staged persistence was unexercised. If the player values obvious steps, do not manufacture friction. If the player reports routine without either value or dislike, experiential value remains unresolved. The proposed condition changes both persistence and the final conjunction relative to the old reset trial; it is not a causal A/B test.
