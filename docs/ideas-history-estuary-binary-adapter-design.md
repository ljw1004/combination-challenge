# Estuary — named binary adapter, working design

A separate logical interaction layer, not a UI, not a 200-decision result. The frozen signal substrate remains unchanged. Every submitted action contains exactly two existing piece IDs; no editable method, actor, channel, process, destination or output-name fields. Compatible pair previews disclose actual consequences. No recipe secrecy, consumable stock, setup quotas or installation prerequisites.

The starting world deliberately supplies useful authored places and tools. Watchhouse observes Sweep; Mirror Quay observes Sweep through reversed movement; Pilgrim Inlet observes Journey through pressure sensing; Lantern Marsh observes Live C through pressure sensing; Mirror Marsh observes Live C through reversed movement; Storm Archive encounters Later D through reversed movement. These sites are explicit situated experiences, not bags into which a player must bind four fields. Each carries a disclosed callable local practice; placing a person there immediately lives the experience and retains its practice. This is an authored abstraction, not simulated geography. Places differ in actual trajectories and embodied practices. Named time/channel tools are ready capabilities, not unlocked by arbitrary primitive recipes.

Person + lived episode immediately teaches and enacts its source, when locally compatible. Two divergent family episodes immediately exchange and enact both memories. There is no teach/install/activate sequence. Score + person immediately enacts, or sends personal instruction to a distant person under the existing delivery law. Every ambiguity has a public fixed rule: a dual-output person uses angle for a dual-channel solo score; single-channel scores determine their own compatible port. Two persons with unambiguous distinct angle/pressure roles create a reusable duo; this genuinely binds two people, and its construction counts. A supplied Beacon Pair visibly means Sori on angle and Ilen on pressure. Score + duo performs together.

Person + Two Roads makes a continuing relative with the actual shared past; person + school transfers its living role immediately when capable. Score + a school's invitation mailbox sends a role invitation. Combining two matching invitations performs the festival when delivery rules permit. Former holders and personal mail remain independent. Actual received invitations, not generic 'festival' badges, are operands.

Adapter gestures, substrate commands and automatic deliveries are three separate ledgers. A gesture may enact multiple causal commands; it is not counted as multiple player decisions. Source-exposed authored routes establish reachability only. No fresh player, human-fun claim or CLI publication is part of this adapter implementation. Logical pair IDs are a test interface for future physical drag/placement, not themselves evidence of physical UI usability.

## Implemented scope and first source-exposed witnesses

`ideas-history-estuary-binary.ts` implements the pair algebra, inspectable pieces, noncommitting preview and compatible-pair discovery. Preview includes named result pieces, resulting episodes/outputs, affected world actors/schools/messages and endpoint changes. Site inspection includes the exact trajectory and local practice. Pieces persist indefinitely. No UI or fresh CLI player was created.

Three constructed variants reach all six existing endpoint predicates: woven (21 gestures / 25 substrate commands), whole-tool (20 / 24), personal-teaching (22 / 26), each with two automatic deliveries. These are variants of one authored collection, **not three independent content scenarios**, not minima, not 20–22 interesting decisions, and not evidence toward 200 meaningful decisions. They demonstrate the entire collection can use pairs without retaining the earlier multi-field programming interface. An immediate episode lesson can contain two substrate commands; a reciprocal exchange contains three. Those are still one gesture each.

The places supply their local following practices even to newcomers. Therefore the later marsh visits demonstrate actual additional experience, but **do not establish that receiving the relative's controller was necessary**. The controller is genuinely transferred by reunion; the openly available situated practice is a legitimate substitute. This adapter chooses comfortable named world interaction over forcing retention gates. No causal claim that the place practice is earned through exchange is made.

Further work must test whether players value the named consequences and generate genuinely different continuations, then introduce new content scenarios if justified. Padding this finite collection with gates, repeated visits, assembly of parameter fields, or compulsory clicks to reach 200 is specifically rejected. The next design question is how a created relationship changes later options or meaning, not how many repetitions of these 21 gestures can be recorded.

## Normal discovery versus developer prediction (latest player preference)

Normal `compatible` hints return **existing partner IDs and names only**. They do not return the future result name, output trajectory or hypothetical world. Existing pieces and their already-public behavior remain inspectable. `preview` is a developer verification facility with rich future output, not the normal player discovery surface. Any trial given `preview` must be labeled preview-exposed, not discovery play. This distinction follows the latest human preference communicated by the coordinator and supersedes the older result-revealing hover assumption for the next whole-play protocol. No new player protocol or player run is launched by this freeze.

Retained pieces are not a clutter defect by themselves. The human's latest workspace preference welcomes a scrolling playspace becoming a catalogue: old things remain where left while useful ones are dragged into new locations. This logical adapter preserves all pieces; it does not implement spatial persistence or scrolling. Future scenario breadth should be motivated by different situations, never merely by reducing retained-token count or forcing a compact screen.
