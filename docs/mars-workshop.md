# Mars Workshop logical campaign

Independent candidate `mars-workshop-1`. This is toy object logic, not Mars engineering. UI work remains frozen. Sources do not import or alter the frozen Mars Objects, Progressive Camp, Living, or Atlas models.

## Current mechanical result

The implemented campaign has **six retained maps and twelve finite jobs**. It is complete as content, but its proposed approximately-200-intervention length is **falsified by fluent legal witnesses**:

| Executed condition | Accepted interventions | Jobs achieved |
| --- | ---: | ---: |
| Ordinary catalogue, suggested order | 74 | 12/12 |
| Complete catalogue | 69 | 12/12 |
| Prior whole-assembly designs actually reused | 60 | 12/12 |
| Ordinary catalogue, reverse map order | 74 | 12/12 |

These are authored mechanical witnesses and best-found upper bounds, not shortest-path proofs, fresh player reports, enjoyment evidence, or measured human duration. Each accepted action is preview/transition checked, and each complete action list replays exactly. The reuse run skips rebuilding nine contextual assemblies, but still reconnects external interfaces and obtains actual observations/site contacts.

The independent adversarial screen found another ordinary/complete/saved-design route of 75/69/56 interventions using a broad reusable outpost. See `docs/mars-workshop-independent-review.md` and `results/mars-workshop-independent/` for its actual scope, source hashes, counterexamples and subsequent fixes. Do not treat inability of the simpler author prefab attack to complete a job as proof that universal construction fails.

All short answers remain legal. There is no target counter, move minimum, concealed recipe, finite stock, production timer or reset-knowledge gate. More named jobs did not establish the required length. The next substantive design should change what projects require, rather than splitting movement/connections into clicks or preventing whole-object reuse. The current short campaign can be preserved and evaluated as short; it is not the requested end state.

## Model and access

- Fifteen familiar primitives and twenty-seven canonical recipes, plus unrestricted player-created assembly designs.
- Ordinary starts with those primitives **and the freely reusable designs of the three kinds of supplied actual objects**: greenhouse, camera and sample case. This is eighteen known designs, not a claim that supplied objects must be rebuilt. Complete starts with all forty-two canonical designs.
- Six boards retain independent objects, links, actual observations and first-achievement certificates. All map selection is free; no world time advances on inactive boards.
- Objects retain inspectable actual part trees, containing versus exterior relationships, pose/facing, identity ancestry, external interfaces and provenance. Joining another actual object preserves its member identity. Design copies create new physical identities and no invented observations/site contacts.
- A supported clear boundary encloses and passes light. Opaque foil encloses, blocks transmitted light and can reflect. Mesh protects against dust while admitting air/light. Covering affects the contents actually inside its tree, not every object at an anchor.
- Exposed solar cells face a public row's source direction; source-derived power drives lamps/heaters. Whole power/water interfaces connect actual objects. A least fixed point starts from actual environmental sources each evaluation: source-free lamp/panel feedback cannot start itself.
- Warmth at ice yields water; an enclosed lit unseeded tray or a mesh/tube passage cleans dirty input. A seed-bearing tray grows when enclosed, lit and clean-water-fed. Drying instead needs a dry lit air-exposed actual sample support.
- Frame plus wheels enables whole-route movement. Public low/narrow places and edges constrain actual shape. A hinged root folds as a whole to low/narrow; this is deliberately a two-category toy law, not articulated rigid-body physics. Explicit route waypoints cost no extra interventions. Any unfolded frame can support a displayed gap.
- Cameras produce actual illuminated subject/viewpoint records. Optical relay/transmission retains their original IDs; copying a design does not. Sample tags require actual tray/plate contact with the named site.
- Up to four public exposure rows are checked automatically. No waits or per-row checks are counted. Goals expose their exact checks, current satisfaction and historical first achievement separately.

**Bounded abstractions:** internal power conduction and same-assembly light interactions are structural, not user-wired circuit simulation; external object-to-object interfaces are explicit and never automatically refitted by copying. Optical paths are cardinal anchor lines. There are no mass/capacity quantities. A record can be relayed to another actual plate and then to a receiver; the original physical recording object may remain protected.

## Public commands

Use `node experiments/mars-workshop-play.ts help` for the exact adapter syntax, or use `inspect` target `cli` for neutral public onboarding. Main command families are `init`, `view`, `catalogue`, `partners`, `inspect`, `preview`, `combine`, `select`, `undo`, `report`, `finish`, and `verify`.

The underlying action is:

```json
{"type":"combine","a":"operand","b":"operand","context":{"operation":"connect","channel":"water"}}
```

Operands are known concept/design names, actual object IDs, or `place:ID`. Omit `context` for ordinary synthesis, placement, travel or attachment. Explicit operations include inside/outside attachment, connection, aim, open/close/fold, sample, observe, transmit and span. `context.part` targets an actual subtree; `context.at` or `context.via` specifies travel waypoints without charging per edge. The public inspect/rules query describes every eligibility predicate. No command orders an unknown finished output.

Ordinary replies show concise action deltas, goals and identities, not every recipe or preview. Explicit catalogue/partner/inspect/preview queries expose the recipes, law conditions, trees and exact effects. Captures preserve exactly the returned public payloads, source hashes, immutable content-addressed states/exposures and event chains. Long sessions need not duplicate the full history in each response.

Undo restores physical prior state and model counters while retaining all learned concepts/designs, the currently selected map and the identity serial floor. Session evidence and cumulative accepted interventions survive; undo itself counts zero. Thus undo cannot manufacture a clean length claim or secretly require rediscovery.

Adding opaque foil to an achieved greenhouse makes current growth false while retaining its genuine prior certificate. The build/copy-all diagnostic made 276 accepted interventions with no completed card; that is explicitly **not** length or fun evidence. The prefab placement-only attack is limited: absence of its necessary source/record interfaces is not an impossibility result.

The prospective empirical framework is `docs/long-play-evaluation-protocol.md`. Do not give this analyst/model guide or any witnesses to a fresh player. No fresh play was recruited by the implementation team, and no claim of human fun or approximately-200 scale is made.
